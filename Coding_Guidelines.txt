# **Python Coding Guidelines – Draft 3**

## **1. General Principles**

1.1. All Python code must be clear, consistent, and maintainable across platforms (Linux, macOS, Windows).
1.2. Code readability takes precedence over brevity.
1.3. Each module should serve a single, well-defined purpose.
1.4. Avoid hard-coded values; use constants, configuration files, or environment variables.
1.5. Apply these conventions consistently across all projects.

---

## **2. File and Module Organization**

2.1. **File Structure**

* Each file should contain related classes, functions, or utilities.
* Limit file length to ~500 lines unless justified.
* Use UTF-8 encoding and Unix-style line endings (`\n`).

2.2. **Module Naming**

* Modules must use **Camel_Case with underscores**:

  ```python
  Data_Parser.py
  User_Interface.py
  Network_Manager.py
  ```

2.3. **Import Statements**

* Imports grouped and ordered as:

  1. Standard library
  2. Third-party libraries
  3. Local project modules
* Separate each group with one blank line.
* Example:

  ```python
  import os
  import sys

  import requests

  from My_Project.Utilities import File_Reader
  ```

---

## **3. Naming Conventions**

3.1. **Functions** → Camel_Case with underscores:

```python
def Calculate_Sum(f_FirstValue, f_SecondValue):
    ...
```

3.2. **Variables** → CamelCase with scope prefixes:

* `l_` → local variable
* `f_` → function argument
* `g_` → global variable

Example:

```python
MAX_TIMEOUT = 10

def Connect_Server(f_HostName, f_Port):
    l_Socket = socket.create_connection((f_HostName, f_Port), timeout=MAX_TIMEOUT)
    return l_Socket
```

3.3. **Classes** → PascalCase:

```python
class DataManager:
    ...
```

3.4. **Constants** → Uppercase with underscores:

```python
DEFAULT_PATH = "/usr/local/app"
MAX_RETRIES = 5
TIMEOUT_SECONDS = 30
```

---

## **4. Code Formatting**

* 4 spaces per indentation level.
* Max line length: 100 characters.
* Two blank lines before top-level definitions, one inside functions.
* Spaces around binary operators, none in keyword arguments.

---

## **5. Functions and Parameters**

* Arguments prefixed `f_`.
* Locals prefixed `l_`.
* Descriptive names, default values immutable.
* Return explicit values or `None`.
* Example:

```python
def Write_Log(f_Message, f_FilePath="app.log"):
    l_LogFile = open(f_FilePath, "a")
    l_LogFile.write(f_Message + "\n")
    l_LogFile.close()
```

---

## **6. Error Handling**

* Catch specific exceptions only.
* Avoid bare `except:`.
* Example:

```python
try:
    l_Result = Perform_Task()
except ValueError as e:
    Log_Error(e)
```

---

## **7. Documentation**

* Docstrings in English (triple quotes).
* Google-style or reStructuredText format.
* Example:

```python
def Calculate_Sum(f_FirstValue, f_SecondValue):
    """
    Calculates the sum of two numeric values.

    Args:
        f_FirstValue (float): First number.
        f_SecondValue (float): Second number.

    Returns:
        float: Sum of inputs.
    """
    return f_FirstValue + f_SecondValue
```

---

## **8. Logging**

* Use `logging` module, not `print()`.
* One logger per module:

```python
import logging
Logger = logging.getLogger(__name__)
Logger.info("Application started")
```

---

## **9. Testing**

* Use `pytest` or `unittest`.
* Test modules mirror main modules, named `Test_*.py`.
* Example:

```python
def Test_Addition():
    assert Calculate_Sum(2, 3) == 5
```

---

## **10. Version Control**

* Branches: `main`, `dev`, `feature/*`.
* Descriptive commit messages in English.
* Do not commit temporary or generated files.

---

## **11. Standard Project Structure**

```
project_name/
│
├── src/                   # Main application code
│   ├── __init__.py
│   ├── main.py
│   ├── controllers/
│   ├── models/
│   └── utils/
│
├── tests/                 # Unit & integration tests
│   ├── __init__.py
│   └── Test_Main.py
│
├── config/                # Config & environment files
├── scripts/               # Automation scripts
├── docs/                  # Documentation
│
├── requirements.txt       # Dependency list
├── pyproject.toml         # Optional, for poetry/black config
├── README.md
└── .gitignore
```

* Use `pathlib` for cross-platform file paths:

```python
from pathlib import Path
l_ConfigPath = Path("config") / "settings.json"
```

---

## **12. Recommended Tooling**

| Purpose        | Tool             |
| -------------- | ---------------- |
| Formatter      | `black`          |
| Linter         | `ruff`, `flake8` |
| Type Checking  | `mypy`           |
| Testing        | `pytest`         |
| Coverage       | `coverage.py`    |
| Security Audit | `pip-audit`      |

* Use `venv`, `poetry`, or `pipenv` to isolate dependencies.
* Ensure `requirements.txt` or `pyproject.toml` is up-to-date.

---

## **13. Cross-Platform Practices**

* Avoid OS-specific paths (`/` vs `\`).
* Prefer `pathlib.Path` for file operations.
* Test scripts under Linux, macOS, and Windows if possible.
* Avoid platform-specific libraries unless conditionally imported.

---

## **14. Continuous Integration**

* Run linting, tests, and coverage automatically.
* Block merges failing CI checks.
* Generate reports for review.

---

## **15. Maintenance**

* Quarterly guideline review.
* Developers responsible for adherence and proposing improvements.
